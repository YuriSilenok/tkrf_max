# Защита трудовых прав — MAX-бот

Бот: https://max.ru/trud_digitalkostroma_bot

Принимает сообщения о нарушениях трудовых отношений и передаёт их администраторам. По умолчанию обращение анонимно для получателей. Ответ по существу через бота не предусмотрен; пользователь может отдельно согласиться передать контакты для личного ответа вне бота.

## Обращения

- `/start` показывает приветствие и условия работы, но не создаёт заявление и не уведомляет администраторов о запуске.
- Поддерживаются текст, фото и видео. Материалы передаются с номером заявления; исходное сообщение от пользователя не пересылается.
- При перерыве не более 10 суток материалы того же пользователя добавляются к текущему заявлению. После большего перерыва создаётся новый номер.
- Администраторы получают номер, содержание и поддерживаемые медиа. Им не добавляются имя, username, MAX ID, геолокация. Время отправки доступно в административном просмотре и выгрузке.
- Если администраторов ещё нет, материалы сохраняются и передаются при последующем назначении администратора.

Анонимность относится к передаче администраторам: внутри приложения хранится связь MAX ID очевидца с заявлением для объединения материалов. Это не обещание отсутствия идентификаторов в системе или анонимности для платформы MAX. Входные метаданные события очищаются после обработки.

## Добровольные контакты

После приёма материалов бот показывает кнопки **друг под другом**: «Хочу получить ответ лично» и «Остаться анонимным».

1. При выборе личного ответа пользователь вводит телефон и/или email; ФИО — по желанию.
2. Бот показывает введённые данные и отдельно просит согласие: «Согласен передать контакты» либо «Остаться анонимным», также отдельными строками.
3. Только после подтверждения контакты сохраняются у заявления и направляются администраторам. Они включаются и в последующие материалы этого заявления.
4. «Остаться анонимным» прекращает дальнейшую передачу сохранённых контактов этого заявления. Уже отправленные сведения через бота отозвать нельзя.

Состояние выбора истекает через 10 минут. После истечения для нового выбора передачи контактов потребуется снова отправить материалы. Автоматические подтверждения приёма не являются ответом по существу.

## Администраторы

Администратор получает заявления и создаёт одноразовое приглашение кнопкой «Создать приглашение» или `/invite`. Срок ссылки — 30 минут, использование однократное. Первоначальное назначение возможно через `ADMIN_IDS` или серверную команду `manage.py labor grant-admin --user-id <MAX_ID>`.

В текущем обработчике сообщения пользователя с ролью администратора не создают обращения очевидца: бот сообщает, что пользователь получает заявления.

## Реализация и запуск

Рабочая версия включена в каталог `src/` этого репозитория. Это общий код трёх приложений; для данного бота укажите `BOT_KIND=labor`. Каждое приложение запускается отдельным процессом с собственной БД и конфигурацией. Описание переменных окружения, запуска и обслуживания: [запуск и обслуживание](docs/runtime.md).

Стек рабочей версии: Python 3.12 на VDS, aiohttp, Peewee, SQLite. События поступают через HTTPS webhook MAX; входящие события и исходящие сообщения сохраняются в SQLite. Диалоги хранятся в БД, срок состояния — 10 минут. `/start` сбрасывает текущий диалог, `/id` показывает MAX ID, «Отмена» отменяет текущий ввод.

Роли проверяются перед действиями; права выдаются одноразовыми приглашениями либо администратором сервера через `manage.py`. Последнюю роль администратора снять через меню нельзя. Секреты и рабочие БД в Git не сохраняются.

Тесты и пробные обращения в ботов по указанию владельца не запускаются.

## Структура репозитория

- src/ — рабочий Python-код и публичная цепочка сертификатов портала.
- deploy/ — скрипты существующего VDS.
- docs/ — документация эксплуатации.
- requirements.txt — закреплённые зависимости рабочей версии.
- .env.example — шаблон конфигурации без секретов.

Установка: python -m pip install -r requirements.txt. После загрузки настроек в окружение: python -B src/app.py. Файл .env автоматически не загружается. Для 'labor' используйте BOT_KIND=labor. Текущие данные хранятся в data/ и не включаются в Git.

### Удаление администратора

В административном меню доступны «Список ролей» и «Снять администратора». Введите MAX ID из списка и подтвердите «Да, снять» либо нажмите «Отмена». Перед удалением права проверяются повторно; последнего администратора удалить нельзя. Удалённый администратор перестаёт получать новые материалы, состояние его диалога очищается. Ожидающие материалы обращений остаются в очереди, но не доставляются без действующей роли администратора; при возвращении роли доставка возобновляется. Сами обращения сохраняются. Меню обновляется командой `/start`. Назначения из `ADMIN_IDS` применяются при запуске приложения: для постоянного удаления такого назначения необходимо также убрать ID из конфигурации.
## Просмотр и выгрузка заявлений

Административное меню: «Просмотр заявления» → номер. Выводятся все сохранённые текстовые сообщения, фотографии и видео, по 10 сообщений за страницу; кнопка «Далее» открывает продолжение. Время показано в МСК. Проверяются действующие права администратора, включая проверку перед доставкой материалов.

«Выгрузить заявления» формирует ZIP-файл и отправляет его в личный диалог администратора. Распакуйте архив и откройте `index.html`. Материалы сгруппированы по номеру заявления: полные тексты, фото в папках `statement-<номер>/`, отметки времени отправки видео. Сами видео в архив не включаются. Для недоступных фотографий явно указана причина; отсутствующие файлы не подменяются. Публичной ссылки на архив нет. Временные файлы сервера закрываются и удаляются после формирования/загрузки.

У новых сообщений сохраняются полный текст, время отправки MAX и внутренний ID исходного сообщения (только для повторного получения вложений, администраторам ID не показывается). Для сообщений до обновления время может быть неизвестно, а не сохранённые ранее фото/видео не восстанавливаются автоматически. Времена не выдумываются. Архив не содержит MAX ID или профиля очевидца; добровольно переданные в составе обращения контакты остаются частью текста.

Фото принимаются по медиа-токену или URL; видео по токену либо через повторную загрузку URL-only вложения в MAX. Для видео с URL используется временный файл и ограничение 250 МБ; сетевые обращения ограничены HTTPS и публичными адресами. Неподдержанные фото/видео вызывают явное сообщение об ошибке. При сбое доставки материалы остаются в очереди; ошибку нельзя считать подтверждением успешной доставки. У пользователя с ролью администратора сообщения по-прежнему не создают обращений очевидца.

Развёртывание: `deploy/update-labor-archive.sh`, архив `/opt/max-bots/labor-archive-update.tar.gz`. До обновления создаётся согласованная копия БД; добавляются поля `sent_at`, `source_mid`, `original_text` без изменения старых записей. Быстрый откат кода: `bash /opt/max-bots/rollback-labor-archive.sh`; текущая БД сохраняется, дополнительные поля совместимы с предыдущим кодом. Тесты и пробные обращения по указанию владельца не запускаются.
