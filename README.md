# Функциональные требования к чат-боту MAX для анонимных сообщений о нарушениях трудовых отношений

## 1. Назначение системы

Чат-бот предназначен для приёма анонимных сообщений о нарушениях трудовых отношений от очевидцев и односторонней передачи этих сообщений администраторам. Обратная связь с очевидцем через бота не предусмотрена.

---

## 2. Стек технологий

| Компонент | Технология |
|---|---|
| Язык программирования | Python 3.10+ |
| ORM | Peewee |
| База данных | SQLite3 |
| Платформа | MAX Bot API |

**Назначение технологий:**
- **Python** — реализация логики бота, обработка сообщений, работа с API MAX.
- **Peewee** — ORM для описания моделей и работы с базой данных.
- **SQLite3** — хранение данных о заявлениях, очевидцах, администраторах и одноразовых ссылках.

---

## 3. Роли

| Роль | Описание |
|---|---|
| Очевидец | Любой пользователь, запустивший бота без приглашения. Может отправить `/start`, текст, фото, видео. |
| Администратор | Назначается только по одноразовой ссылке. Получает уведомления о заявлениях без данных об очевидце. |

---

## 4. Функциональные требования

### FR-01. Запуск бота очевидцем

- При запуске бота без пригласительной ссылки пользователю автоматически назначается роль **Очевидец**.
- Бот отправляет краткое приветственное сообщение.
- Сообщение должно содержать информацию об анонимности и одностороннем характере связи.
- Бот не должен передавать администраторам факт запуска бота очевидцем.

**Текст сообщения:**
> Это анонимный бот для сообщений о нарушениях трудовых отношений. Отправьте текст, фото или видео. Обратная связь по сообщению не предусмотрена.

---

### FR-02. Приём сообщений от очевидца

- Бот принимает от очевидца следующие типы сообщений:
  - текст;
  - фото;
  - видео.
- Иные типы сообщений не входят в поддерживаемые сценарии.
- На каждое принятое сообщение бот отправляет очевидцу короткий автоответ.

**Автоответы:**

| Тип сообщения | Ответ системы |
|---|---|
| Текст | Заявление №{номер} принято. Текст передан администраторам. |
| Фото | Фото принято и добавлено к заявлению №{номер}. Администраторы получат его. |
| Видео | Видео принято и добавлено к заявлению №{номер}. Администраторы получат его. |

---

### FR-03. Присвоение номера заявления

- Одно заявление привязано к одному очевидцу.
- Если между сообщениями одного очевидца прошло **10 суток или меньше**, сообщение добавляется к текущему заявлению. Номер заявления не меняется.
- Если между сообщениями прошло **более 10 суток**, следующее сообщение считается новым заявлением и получает новый номер.
- Внутри системы бот хранит в SQLite3 (через Peewee):
  - внутренний ID очевидца;
  - номер текущего заявления;
  - дату и время последнего сообщения.

---

### FR-04. Анонимность для администратора

- Администратор получает уведомления только с номером заявления и содержимым сообщения.
- Администратору **не передаются**:
  - имя очевидца;
  - username;
  - ID пользователя;
  - дата и время отправки;
  - геолокация;
  - количество предыдущих обращений;
  - любые другие персональные или служебные данные очевидца.

---

### FR-05. Уведомления администратора

- При новом заявлении администратору отправляется уведомление:
  > 📄 Заявление №{номер}  
  > Содержание: {текст / подпись / медиа}

- При продолжении текущего заявления администратору отправляется уведомление:
  > 📄 Заявление №{номер} (продолжение)  
  > Содержание: {текст / подпись / медиа}

- Уведомление при `/start` очевидца администратору не отправляется.

---

### FR-06. Назначение администратора

- Роль **Администратор** назначается только по одноразовой ссылке.
- Администратор может создать приглашение командой `/invite`.
- Бот генерирует одноразовую ссылку вида:
  > `https://max.ru/<bot_username>?start=inv_<token>`
- Ссылка действует 30 минут.
- Количество использований: 1.
- При переходе по действительной ссылке пользователю назначается роль администратора.
- При переходе по недействительной, истёкшей или уже использованной ссылке пользователь остаётся очевидцем.
- Все данные о токенах и администраторах хранятся в SQLite3 (через Peewee).

---

### FR-07. Односторонний канал связи

- Очевидец не получает ответов по существу обращения.
- Администратор не может ответить очевидцу через бота.
- Все ответы очевидцу носят только информационный характер: подтверждение приёма сообщения.

## 6. Критерии приёмки

1. Очевидец при `/start` получает краткое сообщение, содержащее слово «анонимный» и предупреждение об отсутствии ответа.
2. Очевидец может отправить текст, фото и видео.
3. Администратор не получает данных об очевидце.
4. Администратор получает номер заявления и содержимое сообщения.
5. При паузе более 10 суток между сообщениями создаётся новое заявление с новым номером.
6. Роль администратора назначается только по одноразовой ссылке.
7. Ссылка действует 30 минут и может быть использована один раз.
8. Все данные (очевидцы, заявления, сообщения, администраторы, токены) сохраняются в SQLite3 с использованием ORM Peewee.
9. Приложение реализовано на Python 3.10+.
